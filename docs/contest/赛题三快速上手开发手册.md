# 赛题三项目知识地图与快速上手手册

适用方案：`RK3568_MES2L100H`，RK3568J + `PG2L100H` FPGA，FMC HDMI 输入，FPGA 实时视频处理与感知前端，PCIe 高速通信，RK3568 MCU/主控负责高层感知、数据交互和指令控制。

这份文档的目标是帮助你**全面理解项目需要的知识，并按正确顺序进入开发**。不要求一开始学完所有内容：先理解系统边界，再做最小闭环，最后扩展高阶功能。

## 1. 项目本质

赛题三的核心是基于 FPGA 建立道路环境监测和特定场景感知的实时前端，同时设计 MCU 与 FPGA 之间的高速通信机制，完成数据交互与指令控制。复杂目标分类、场景理解和多帧决策由 RK3568 协同完成；RKNN/NPU 是高层感知的主要实现选项：

```text
外部 HDMI 视频
  -> FMC HDMI 接收子卡
  -> FPGA HDMI RX / 像素流
  -> FPGA 预处理、特征提取与候选感知
  -> FPGA 结果/状态缓存
  -> PCIe 数据交互与指令控制
  -> RK3568 Linux 驱动、高层感知、决策、显示和记录
  -> HDMI OSD / LED / UART 输出
```

每个部件的职责不同：

| 部件 | 解决的问题 |
|---|---|
| HDMI RX | 把 HDMI 电气信号还原为像素时钟、视频数据和行帧时序 |
| FPGA | 完成确定性、并行、低延迟的像素处理、道路特征提取、候选生成和快速状态 |
| DDR3 | 暂存视频帧，隔离采集、传输和处理的速度差异 |
| PCIe | 在 FPGA 和 RK3568 之间高速搬运感知结果、状态、配置、指令和可选图像数据 |
| RK3568 Linux | 管理驱动、内存、文件、应用和系统状态 |
| RKNN/NPU | 目标分类、复杂场景理解和多帧感知融合 |
| OpenCV/规则 | RK 侧后处理、决策、显示、记录和结果复核 |
| FPGA 状态机 | 前端快速状态、硬件告警和低延迟保护 |

## 2. 已确认事实和必须确认的未知项

### 已确认事实

- 目标板是 `RK3568_MES2L100H`，组合为 RK3568J + `PG2L100H` FPGA；
- 厂商赛题架构建议使用 **FMC 转 HDMI 子卡**接入 1080P HDMI 视频；
- 厂商建议 FPGA 通过 PCIe DMA 将 ROI 或处理后的全帧写入 RK3568 内存；
- 本地官方例程主要是 `MES50HP + PGL50H`，只能作为移植参考；
- 单路 HDMI 可以作为基础闭环；单路不能直接满足四路并行高阶要求。

### 开始写 HDL 前必须确认

| 未知项 | 影响 |
|---|---|
| FMC HDMI 子卡型号和 HDMI RX 芯片 | 决定 TMDS 管脚、I2C 配置、时钟和 PDS IP |
| PG2L100H PCIe IP、DMA 示例和约束 | 决定 FPGA 端点能否与 RK3568 建链并传输 |
| PCIe lane 数、端点角色和参考时钟 | 决定实际吞吐，不能只看宣传参数 |
| RK3568 Linux 镜像、设备树和驱动 | 决定 BAR、MSI、DMA 和缓存是否可用 |
| DDR3 型号、位宽、控制器配置 | 决定帧缓存容量和带宽 |
| HDMI 输出路径 | 可能走 RK3568 HDMI，也可能走 FPGA HDMI TX，必须实物确认 |
| 四路输入硬件 | 决定是否有资格和能力实现四路独立视频 |

## 3. 需要掌握的完整知识体系

下面按项目依赖关系排列。带“P0”的是基础闭环必学；“P1”是高阶和优化必学；“P2”可以最后再学。

### 3.1 数字逻辑与 Verilog/SystemVerilog（P0）

需要掌握：

- 组合逻辑、时序逻辑、寄存器、计数器、状态机；
- `always_ff/always_comb` 或规范的时序/组合写法；
- 同步复位、异步复位、低有效复位；
- 参数化模块、模块例化、接口位宽和时序；
- 仿真波形、断言、testbench 和综合可实现性；
- 时序约束、建立保持时间、时钟频率和资源利用率。

必须形成的思维：HDL 描述的是硬件电路，不是顺序执行的软件。一个 `always` 块、一个时钟域、一个复位条件都可能对应真实的寄存器和组合路径。

暂时不用深入：CPU 设计、复杂流水线、VHDL、RISC-V 内核。这些不是赛题三首版的必要知识。

### 3.2 PDS 工具和 FPGA 工程（P0）

需要掌握：

- 创建目标器件工程；
- 添加 RTL、IP 和约束文件；
- IP Compiler 的配置和版本管理；
- 时钟/PLL、DDR3、HSST/PCIe IP 的生成；
- 综合、布局布线、时序报告、资源报告；
- bitstream/sbit 生成、下载和 Flash 固化；
- 管脚约束、电气标准、差分对、IO 电压和时钟管脚。

官方 50K 例程可以用来学习流程，但不能直接假设其 `PGL50H` 约束适用于 `PG2L100H`。

### 3.3 HDMI 视频基础（P0）

你们不是从摄像头 DVP 输入，而是从 HDMI 接收芯片输入，所以要理解两层：

1. **物理/接收层**：TMDS、差分时钟、HDMI RX 芯片、I2C 配置、锁定状态；
2. **视频流层**：像素时钟、`DE`、`HSYNC`、`VSYNC`、分辨率、帧率和像素格式。

重要概念：

- `pixel_clk`：像素数据采样时钟；
- `DE`：有效视频区域标志；
- `HSYNC/VSYNC`：行和帧的边界；
- `RGB888`：每像素 24 bit；
- `RGB565`：每像素 16 bit；
- `YUV422`：常用于降低带宽；
- `width/height/stride`：宽、高、每行实际字节数；
- `frame_start/frame_end`：系统内部定义的帧边界。

开发顺序必须是：彩条/测试图案 -> HDMI IN 直通 -> DDR3 缓存 -> 叠加标记 -> PCIe 传输。不要一开始就把 AI 算法插进视频时序链路。

### 3.4 时钟域 crossing 和视频流握手（P0）

HDMI 像素时钟、DDR3 用户时钟、PCIe 用户时钟和 RK3568 CPU 时钟可能不同，因此必须理解：

- 单 bit 状态如何用双触发器同步；
- 脉冲如何跨时钟域；
- 多 bit 数据如何用异步 FIFO 或握手协议跨域；
- FIFO 满/空、backpressure 和丢帧处理；
- 复位释放顺序和跨域复位同步。

视频系统最常见的错误不是算法，而是 CDC、行边界和复位导致的花屏、撕裂、偶发死锁。

### 3.5 DDR3、帧缓存和内存所有权（P0）

DDR3 需要解决的不是“能不能读写”，而是“谁在什么时候拥有哪一块缓冲区”：

```text
FPGA 写帧 -> 标记 frame_ready -> RK 读取/推理 -> RK 释放 buffer -> FPGA 复用
```

必须掌握：

- DDR3 控制器初始化和校准；
- AXI/类 AXI 用户接口、突发读写和对齐；
- ping-pong buffer；
- ring buffer；
- 帧完成标记、帧号和 CRC；
- 写入端、读取端和释放端的 ownership；
- 复位、超时、丢帧和错误恢复。

首版至少使用两个帧缓存；不要在没有 ownership 约定的情况下直接读写共享内存。

### 3.6 PCIe、BAR、PIO、MSI 和 DMA（P0）

PCIe 必须拆成控制面和数据面：

| 机制 | 作用 | 数据规模 |
|---|---|---|
| BAR/PIO | 启停、状态、参数、错误计数、心跳 | 小 |
| MSI/MSI-X | 新帧、完成、错误通知 | 事件 |
| DMA | 图像帧、ROI、描述符和大块数据 | 大 |

需要掌握：

- Endpoint 和 Root Complex 的角色；
- BAR 地址空间和寄存器映射；
- DMA 源地址、目标地址、长度和完成状态；
- 描述符 ring 和生产者/消费者索引；
- cache coherency、DMA mapping 和内存屏障；
- 中断合并、超时、链路复位和错误恢复；
- PIO 成功不等于 DMA 成功。

图像 payload 不能使用 UART、I2C 或 FSPI 搬运。PCIe 的实际有效吞吐必须用已知模式和真实帧实测。

### 3.7 RK3568 Linux、设备树和驱动（P0）

需要理解：

- Linux 启动、设备树、内核模块和用户态设备文件；
- PCIe host/endpoint 配置；
- BAR 映射、`mmap`、`ioctl`、中断和 DMA buffer；
- DMA 内存的缓存一致性；
- `dmesg`、`lspci` 或平台等效工具、`/dev` 节点和 sysfs；
- 用户态 C/C++ 应用与驱动的接口。

首版不要同时修改复杂 BSP。先确认厂商镜像能识别 PCIe 设备，再逐步添加自己的驱动和应用。

### 3.8 C/C++、OpenCV 和视频应用（P0）

需要掌握：

- 图像读取、颜色空间转换、缩放和 ROI；
- BGR/RGB/YUV 的通道顺序；
- 二值化、形态学、边缘检测和轮廓；
- 视频帧循环、时间戳和帧号；
- OSD、箭头、文本和报警框；
- 日志、性能计时和离线回归。

OpenCV 可用于 RK3568 侧结果复核、OSD、日志和离线回归；不得把 ARM-only 识别基线当作 FPGA 感知功能的替代。

### 3.9 RKNN Toolkit2 和 NPU 部署（RK 高层感知路径）

核心链路：

```text
模型选择/训练 -> ONNX 或厂商格式 -> RKNN 转换 -> 量化 -> Runtime -> 前后处理
```

需要掌握：

- 输入尺寸、通道顺序和归一化；
- ONNX 导出和算子支持；
- INT8/混合量化；
- NPU 输入输出 tensor；
- 前处理、推理和后处理的分段耗时；
- 置信度、NMS、分割 mask 和 ROI；
- CPU/NPU 内存拷贝和零拷贝的代价。

RKNN 用于 FPGA 前端结果之上的目标分类、复杂场景理解和多帧融合。首版必须先完成 FPGA 前端和通信闭环，再接入 RKNN；不要用 RKNN 结果替代 FPGA 的实时采集、预处理和候选提取。

### 3.10 计算机视觉和 ADAS 感知（P0/P1）

赛题需要的感知任务可以拆成：

| 任务 | 推荐首版方法 | 后续提升 |
|---|---|---|
| 行人/车辆/路障 | 轻量目标检测模型 | 自定义数据微调、多帧跟踪 |
| 红绿灯候选 | 检测模型或固定 ROI | 颜色/亮度/时序稳定 |
| 红黄绿分类 | HSV/亮度规则 + ROI | 小目标专用分类模型 |
| 车道/斑马线 | 分割模型或颜色/边缘规则 | 透视变换、专用车道模型 |
| 实线/虚线 | 车道 mask、连通性、间断率 | 时序滤波、几何拟合 |
| 碰撞提醒 | 障碍物框、距离/面积变化 | 多帧跟踪和速度估计 |

不要一开始追求一个模型完成所有任务。先让每个赛题动作有稳定输入，再优化精度。

### 3.11 决策状态机和安全逻辑（P0）

感知结果不是动作，必须经过状态机：

```text
输入帧 -> 感知结果 -> 置信度/有效期判断 -> 规则优先级 -> final_action
```

建议优先级：

```text
故障/急停 > 红灯停车 > 碰撞停车 > 实线禁止变道 > 允许导航动作 > 正常行驶
```

需要处理：置信度不足、连续多帧确认、输入失锁、模型超时、PCIe/DMA 错误、强制通行和强制变道指令，以及默认安全动作。

### 3.12 HDMI OSD 和输出链路（P0）

需要掌握：

- OSD 是在视频输出路径叠加，不应破坏原始帧同步；
- 叠加数据必须绑定 `frame_seq`；
- 输出箭头、停车、报警颜色和文字要有固定布局；
- 输出链路要区分 RK3568 HDMI 输出和 FPGA HDMI TX 输出；
- 如果 RK3568 负责最终显示，FPGA 负责采集、实时前端处理和候选提取；
- 如果 FPGA 负责直通显示，必须定义 RK 高层结果如何回传到 FPGA。

### 3.13 多路视频、同步和扩展（P1）

四路高阶不是简单复制四份模块。需要理解：

- 每路必须有独立 `channel_id`；
- 每路有独立的锁定、帧号、时间戳和错误计数；
- DDR3 需要多路缓存和仲裁；
- PCIe 需要多路 DMA ring 或统一调度器；
- RK3568 需要多路推理调度、ROI 策略或批处理；
- 多路结果要按通道和帧号融合；
- 一路失锁不能拖死其他通道。

如果只有一块 HDMI 输入子卡，应把项目目标定义为单路基础系统，不能把同一视频复制成四路来宣称高阶完成。

### 3.14 性能工程（P1）

必须分别测量：HDMI RX 锁定和像素时钟、FPGA 预处理延迟、DDR3 写入/读出带宽、PCIe PIO 延迟和 DMA 有效吞吐、RKNN 前处理/推理/后处理耗时、端到端输入到 OSD 延迟、帧率/丢帧率、CPU/NPU 利用率、内存占用，以及 FPGA LUT/寄存器/BRAM/eRAM/DSP 和时序裕量。

视频带宽近似值：

| 视频 | RGB888 | YUV422 |
|---|---:|---:|
| 1080P@30 单路 | 186.6 MB/s | 124.4 MB/s |
| 1080P@60 单路 | 373.2 MB/s | 248.8 MB/s |
| 1080P@30 四路 | 746.4 MB/s | 497.7 MB/s |

这些只是 payload，不包含协议、描述符、空闲、缓存和调度开销。

### 3.15 验证和故障恢复（P0/P1）

必须建立分层验证：

1. RTL 仿真：FIFO、CDC、帧边界、复位、状态机；
2. FPGA 单模块：LED、DDR3、HDMI RX、PCIe PIO；
3. FPGA-RK 联调：已知模式 DMA、真实单帧、连续帧；
4. 应用回归：固定视频、固定结果、固定日志；
5. 长稳测试：连续运行、丢帧、失锁、复位、DMA 错误和内存回收。

错误必须可观察：输入失锁、DDR3 错误、PCIe 链路错误、DMA 超时、模型超时和帧丢失都应有计数器或日志。

## 4. 三个必须冻结的数据接口

### 4.1 FPGA -> RK3568 前端感知结果描述符

```text
result_seq, frame_seq, channel_id, capture_time_us,
feature_type, candidate_type, candidate_count, fast_state,
buffer_dma_addr, byte_count, crc32, producer_state
```

### 4.2 RK3568 -> FPGA 控制消息

```text
start, stop, reset, input_format, roi_enable,
buffer_release_index, heartbeat, test_pattern
```

### 4.3 RK3568 -> FPGA 高层结果与控制反馈

```text
result_seq, frame_seq, channel_id,
scene_type, final_class, final_confidence,
navigation_action, display_flags, alarm_code
```

协议要固定：字段宽度、字节序、版本号、CRC、超时、错误码和 ownership。不同模块不能各自定义字段。

## 5. 从零开始的正确学习顺序

### 阶段一：先理解系统，不写复杂功能

阅读顺序：

1. [赛题指南](../../资料/紫光.pdf) 第 12-16 页；
2. [官方历程能力与赛题三映射](官方历程能力与赛题三映射.md)；
3. FMC HDMI 子卡资料；
4. PG2L100H PCIe/DMA 资料；
5. RK3568 Linux 镜像和 RKNN 版本说明。

此阶段的结果应该是能画出数据流，并解释每个模块的输入、输出、时钟和错误状态。

### 阶段二：建立 FPGA 视频基础

顺序：LED/时钟/复位 -> I2C 配置 HDMI RX -> HDMI 彩条或直通 -> DDR3 初始化和读写 -> HDMI 写入 DDR3 再读出 -> 添加帧号、CRC、丢帧和失锁状态。

### 阶段三：建立 PCIe 和 Linux 基础

顺序：PCIe 枚举 -> BAR/PIO 寄存器读写 -> MSI/中断 -> 已知模式 DMA -> 真实单帧 DMA -> 连续帧 DMA、ownership 和复位恢复。

### 阶段四：建立 FPGA 前端与 RK 高层感知基础

使用固定测试图像或仿真像素流，在 FPGA 中完成颜色/边缘/几何特征、候选区域和快速状态，输出 result_seq、frame_seq、告警和候选信息；在 RK3568 中完成目标分类、复杂场景理解、多帧融合和最终决策。

### 阶段五：单路全链路

```text
HDMI RX -> FPGA 前端处理/候选提取 -> 结果/ROI DMA
                                      -> RK3568 高层感知/决策/显示
                                      <- PCIe 指令/参数/ACK
```

先传结构化前端结果，再按高层感知需要传 ROI/完整帧。先证明结果、决策和指令正确，再追求速度。

### 阶段六：基础功能回归

- 红灯：停车；
- 绿灯：通行；
- 强制通行：报警；
- 虚线：允许变道；
- 实线：保持直行；
- 强制实线变道：报警；
- 行人/路障：提示或停车。

### 阶段七：高阶扩展

四路硬件输入可获得后，再按“分别锁定/编号 -> 四路 DDR3 缓存和 DMA -> 四路 RKNN 调度和融合 -> 夜间/强光/遮挡 -> 满负载优化”的顺序推进。

## 8. 第一周学习和动手清单

| 天数 | 目标 |
|---|---|
| Day 1 | 看懂赛题三要求，画出 HDMI-FPGA-PCIe-RK3568 数据流 |
| Day 2 | 安装 PDS/Linux/RKNN 环境，跑通 LED 和一个 RKNN 示例 |
| Day 3 | 完成 DDR3 初始化和 PCIe 枚举/PIO |
| Day 4 | 完成 FMC HDMI RX 配置和 HDMI 直通 |
| Day 5 | 完成单帧 DDR3 缓存和已知模式 DMA |
| Day 6 | 用文件视频验证 RK3568 高层感知、决策规则和 OSD，输入格式对齐 FPGA 前端结果 |

第一周的目标不是四路，而是证明三件事：HDMI 能进入 FPGA，PCIe 能搬运一帧，RK3568 能对一帧做出决策。

## 9. 性能和带宽的基本判断

未压缩视频 payload 近似为：

```text
带宽 = 宽 × 高 × 每像素字节数 × 帧率
```

典型值：

| 视频 | RGB888 | YUV422 |
|---|---:|---:|
| 1080P@30 单路 | 186.6 MB/s | 124.4 MB/s |
| 1080P@60 单路 | 373.2 MB/s | 248.8 MB/s |
| 1080P@30 四路 | 746.4 MB/s | 497.7 MB/s |

实际还要加上协议、描述符、空闲、缓存和调度开销。首版建议单路、低分辨率或 ROI、YUV/缩放后传输。

## 10. 验收标准

| 模块 | 通过标准 |
|---|---|
| HDMI RX | 分辨率、帧率、锁定正确，连续运行无花屏/丢行 |
| DDR3 | 写入/读出 CRC 一致，复位后能重新初始化 |
| PCIe PIO | BAR 寄存器读写稳定，状态和错误可读取 |
| PCIe DMA | 已知模式正确，至少 1000 次循环无错误 |
| 帧协议 | 帧号、长度、格式和 ownership 不错乱 |
| RKNN | 固定测试集输出稳定，延迟和内存可记录 |
| 决策 | 相同输入得到一致动作，优先级不冲突 |
| OSD | 结果与同一 `frame_seq` 的视频对齐 |
| 四路 | 每路独立编号、缓存、传输、推理和错误统计 |
| 长稳 | 满负载无死锁、无持续丢帧、无缓冲区泄漏 |

## 11. 常见误区

| 误区 | 正确做法 |
|---|---|
| 直接把 50K/PGL50H 例程烧到目标板 | 替换 PG2L100H 管脚、IP、时钟和约束 |
| 先做四路再做单路 | 先完成单路基础版本，四路作为后续扩展 |
| 先训练大模型 | 先用已支持 RK3568 的模型建立基线 |
| 用 CPU memcpy 搬所有视频 | 使用 PCIe DMA，PIO 只搬控制信息 |
| 只看 PCIe 枚举成功 | 继续验证 PIO、DMA、缓存一致性、复位和长稳 |
| 模型结果直接变成动作 | 经过统一决策状态机和安全优先级 |
| 没有帧号 | 每个帧、结果和日志都带 `frame_seq` |
| 没有真实四路硬件就宣布四路完成 | 先确认独立输入和实际吞吐证据 |

## 12. 暂时不需要深入的内容

- RISC-V CPU 内核和 Cache 设计；
- 复杂 SoC 总线互联；
- 大型自动驾驶框架和 ROS2；
- 训练超大模型和从零设计检测网络；
- FPGA 全帧浮点神经网络加速；
- 四路之前的多板级联和光纤协议扩展。

这些内容可能在后续优化中有用，但不会帮助你快速完成首个可运行闭环。

## 13. 当前项目的完成定义

### 基础系统完成

- HDMI 单路输入稳定；
- FPGA DDR3 帧缓存可靠；
- FPGA 能完成实时前端处理、特征/候选提取和快速状态；
- RK3568 能完成目标分类、场景理解、多帧融合和最终决策；
- PCIe 能传输真实感知结果、状态和指令；
- RK3568 能完成结果接收、显示、记录、指令控制和高层感知；
- 红绿灯、变道、行人/路障场景通过回归；
- 有帧号、错误计数、丢帧和延迟统计；
- 连续运行无死锁、缓冲区泄漏和持续性帧错位。

### 高阶系统完成

在基础系统之上，再满足：

- 四路真实独立输入；
- 四路独立缓存、DMA、推理和结果；
- 夜间、强光、遮挡和复杂路口处理；
- 满负载下仍有明确的吞吐、帧率、延迟和错误恢复结果。
