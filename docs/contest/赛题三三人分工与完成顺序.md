# 赛题三三人分工与完成顺序

适用方案：`RK3568_MES2L100H + PG2L100H`，FMC 转 HDMI 子卡输入，FPGA 实时视频处理与感知前端，PCIe 高速通信，RK3568 MCU/主控负责高层感知、指令、数据交互和显示。

## 1. 总体策略

先完成**FPGA 单路实时感知前端 + RK3568 高层感知/高速通信控制闭环**，再扩展四路和复杂场景。三人共享一个固定数据接口，避免各自写一套临时协议。

```text
HDMI RX -> FPGA 采集/预处理/特征与候选提取
                    -> 结果/ROI DMA -> RK3568 高层感知/显示/记录
                    <- PCIe PIO/命令/参数/ACK
```

### 基础要求的目标

- 一路 HDMI 视频稳定输入、缓存和输出；
- FPGA 完成道路视频实时处理、特征/候选提取和快速状态；RK3568 完成目标分类、场景理解和最终判断；
- FPGA 与 RK3568 通过 PCIe 完成结构化结果、状态、参数和指令交互；
- 完成停车、通行、变道、报警和视频叠加；
- 能跑通赛题提供的十字路口、变道、红绿灯和行人场景。

### 高阶要求的目标

- 至少四路逻辑独立的视频流并行采集和低延迟传输；
- 夜间、强光、复杂路口等场景增强；
- 多路 FPGA 实时前端感知、RK3568 高层感知、结果交互和辅助驾驶决策；
- 有资源、时序、帧率、端到端延迟和错误恢复数据。

## 2. 三人职责

### A：FPGA 视频前端负责人

负责从 HDMI 物理输入到 FPGA 前端特征/候选结果和 PCIe 数据面的全部逻辑。

| 阶段 | 交付物 |
|---|---|
| 板卡 bring-up | PDS 工程、时钟/复位、LED、FMC HDMI RX 管脚和 I2C 配置 |
| 视频输入 | HDMI RX 初始化、分辨率检测、RGB/YUV 接收、行场有效信号、像素计数 |
| 缓存 | DDR3 初始化、ping-pong/ring buffer、帧号、丢帧和 CRC 统计 |
| FPGA 预处理 | 可选灰度、RGB/YUV 转换、缩放、ROI、Sobel/阈值等低延迟流水线 |
| FPGA 感知前端 | 红绿灯、车道/实虚线、斑马线、行人/障碍物候选和快速状态 |
| FPGA 结果输出 | 结构化感知结果、告警、建议动作、帧号/结果序号和错误状态 |
| 高阶扩展 | 多 HDMI/FMC/SFP 输入、四路同步、通道编号、输入调度和带宽控制 |
| 验收 | PDS 综合/布局布线、时序无明显违例、HDMI 直通稳定、帧 CRC/行计数正确 |

A 不负责训练模型和 RK3568 应用逻辑，但必须提供稳定的感知结果描述符、命令应答和错误状态。

### B：RK3568 主控与应用负责人

负责 Linux、PCIe 驱动、指令控制、结果接收、目标分类、场景理解、决策、日志和视频结果显示；RKNN/OpenCV 用于高层感知和结果融合。

| 阶段 | 交付物 |
|---|---|
| 通信基线 | 完成 PCIe 枚举、BAR/PIO、MSI、结果 DMA 和命令 ACK |
| 结果处理 | 接收 FPGA 感知结果，检查序号、CRC、通道和有效期 |
| 高层感知 | 使用 RKNN/OpenCV 完成目标分类、场景理解、多帧融合和结果复核 |
| 输出显示 | HDMI OSD、左/右/直行箭头、停车/报警提示、调试日志 |
| 高阶扩展 | 多路结果调度、可选 ROI 推理、日志、夜间/强光协同和延迟优化 |
| 验收 | 结果与 result_seq/frame_seq 对齐，命令 ACK/NACK、延迟、内存和错误统计可记录 |

B 应先完成 PCIe 协议和结果消费的模拟测试；可用文件视频或仿真结果验证高层感知、显示和决策，但最终必须接入 FPGA 前端结果。

### C：PCIe、协议与系统集成负责人

负责 FPGA-RK3568 边界、驱动、状态机、联调和最终演示。

| 阶段 | 交付物 |
|---|---|
| 供应商交接 | 固定 PDS、PCIe IP、RK Linux、设备树、驱动和 RKNN Runtime 版本 |
| PCIe 控制面 | Endpoint/Root Complex 角色、BAR、PIO 寄存器、中断、复位恢复 |
| PCIe 数据面 | DMA 描述符、环形队列、缓存一致性、超时、错误计数和 backpressure |
| 系统控制 | 指令下发、模式/阈值配置、ACK/NACK、结果有效期和安全优先级 |
| 高阶扩展 | 多路帧队列、通道调度、帧同步、吞吐和端到端延迟测量 |
| 验收 | PCIe 枚举、PIO 读写、已知模式 DMA、1000 次循环、联调日志和演示脚本 |

C 不应等到最后才介入；PCIe 描述符、感知结果消息和指令 ACK 必须在单路视频前冻结。

## 3. 三个必须冻结的接口

### 3.1 FPGA -> RK3568 感知结果描述符

```text
result_seq, frame_seq, channel_id, capture_time_us,
feature_type, candidate_type, candidate_count, fast_state,
alarm_code, suggested_action, confidence,
buffer_dma_addr, byte_count, crc32, producer_state
```

规则：FPGA 写完结果和描述符后才移交 ownership；RK3568 读取、记录或可选处理完成并释放缓冲区后，FPGA 才能复用该缓冲区。

### 3.2 RK3568 -> FPGA 指令和参数消息

```text
start, stop, reset, mode, command, threshold_config,
roi_enable, buffer_release_index, heartbeat,
test_pattern, command_seq, ack_required
```

规则：控制面使用 PIO/中断，感知结果使用 DMA；原始图像只作为调试或可选增强数据，不能用 UART 或 FSPI 搬运高速数据。

### 3.3 FPGA -> RK3568 前端感知结果

```text
result_seq, frame_seq, channel_id,
feature_type, candidate_type, candidate_count,
fast_state, confidence, alarm_code
```

FPGA 实时安全状态优先于 RK3568 上层命令：故障/急停 > 红灯停车 > 碰撞停车 > 实线禁止变道 > 允许导航动作 > 正常行驶。

## 4. 推荐完成顺序

### M0：第 0 阶段，硬件和资料冻结

三人共同完成，C 负责记录版本。

- 获得 FMC HDMI 子卡型号、HDMI RX 芯片手册、PDS 工程和管脚约束；
- 获得 PG2L100H PCIe IP、DMA 示例、RK3568 设备树和驱动；
- 固定 PDS、Linux、PCIe 驱动、RKNN Toolkit/Runtime 版本；
- 确认输入分辨率、像素格式、帧率和 HDMI 输出路径。

**未完成 M0，不开始四路扩展。**

### M1：单板和 HDMI 直通

- A：LED、时钟、复位、HDMI RX、I2C、视频时序和直通输出；
- B：准备固定场景视频、标注规则和 PC/RK3568 离线算法测试；
- C：建立版本库、测试记录模板和 PCIe 端点配置清单。

验收：HDMI 输入至少连续运行 30 分钟，分辨率/帧率正确，无明显花屏、丢行或失锁。

### M2：DDR3 帧缓存和 FPGA 预处理

- A：DDR3 ping-pong/ring buffer、帧号、CRC、丢帧统计；
- B：定义 RK3568 结果消费、显示和可选增强需要的输入/结果格式；
- C：定义 DMA 描述符和 buffer ownership。

验收：同一帧写入和读出内容 CRC 一致，连续测试无 ownership 冲突。

### M3：FPGA 前端和 RK3568 高层感知控制闭环

- A：完成颜色/边缘/几何特征、候选区域、快速状态和结果描述符；
- B：接收模拟/真实前端结果，完成目标分类、场景理解、显示、记录、指令下发和 ACK/NACK；
- C：完成命令、参数、状态、错误码和结果有效期的协议测试。

验收：FPGA 可独立输出稳定的前端特征/候选/快速状态，RK3568 可完成高层感知、正确消费结果并控制 FPGA 模式、阈值和测试图案。

### M4：PCIe PIO、DMA 和单路全链路

- A：提供 FPGA 侧 BAR 状态寄存器、感知结果描述符和 DMA 请求；
- B：接收结果/ROI DMA，完成 RKNN/OpenCV 高层感知、显示和记录；
- C：完成驱动、PIO、MSI/中断、DMA ring、缓存一致性和复位恢复。

验收顺序：

1. PCIe 枚举；
2. PIO 读写固定寄存器；
3. FPGA/RK 已知模式 DMA；
4. 真实 FPGA 感知结果 DMA；
5. 连续结果消费、指令 ACK 和 OSD；
6. 1000 次无错误循环。

### M5：基础要求封版

三人共同完成单路演示：

```text
HDMI 视频 -> FPGA 采集/DDR3/前端处理 -> 结果/ROI DMA
          -> RK3568 高层感知/决策/指令控制 -> HDMI OSD + LED/UART
```

基础要求封版标准：

- 四类赛题视频均能运行；
- 红灯停车、绿灯通行、强制通行报警成立；
- 虚线允许变道、实线直行、强制变道报警成立；
- 行人/路障场景能触发提示或停车；
- 感知结果与输入 frame_seq/result_seq 对齐；
- 指令有 ACK/NACK，过期指令不会覆盖 FPGA 安全状态；
- 有资源、时序、帧率和端到端延迟记录。

**只有 M5 稳定后，才进入高阶任务。**

### M6：四路视频高阶扩展

- A：增加 HDMI/FMC/SFP 输入或四路复用解码，维护 channel_id 和同步；
- B：实现多路结果消费、按通道显示/记录和可选 ROI 推理；
- C：扩展多路 DMA ring、通道仲裁、时间戳、丢帧和故障隔离。

验收：四路必须是逻辑独立的视频流，能够分别编号、缓存、传输和给出结果；不能用同一帧复制四份冒充四路。

### M7：复杂场景和系统测试

- 夜间、强光、复杂路口、遮挡和输入失锁恢复；
- 统计四路吞吐、端到端延迟、帧丢失、NPU 利用率和 FPGA 资源；
- 整理源码、架构图、时序图、测试数据和故障说明，形成可复现的工程记录。

## 5. 不同阶段的优先级

| 优先级 | 必须完成 | 可以延期 |
|---|---|---|
| P0 | 单路 HDMI、DDR3、FPGA 前端处理、RK3568 高层感知、PCIe、指令控制和稳定运行验证 | 四路输入、复杂增强、模型大改 |
| P1 | 红绿灯/行人/路障/车道线稳定性、结果交互、OSD、错误恢复 | 光纤扩展、以太网远程配置 |
| P2 | 四路并行、夜间/强光、多模型调度和性能优化 | 非必要的通用框架重构 |

## 6. 关键风险和应对

| 风险 | 责任人 | 应对 |
|---|---|---|
| FMC HDMI 子卡或 PDS IP 未拿到 | C 主责，A 配合 | M0 设为阻塞门；先用离线视频验证 B 的算法 |
| PCIe IP/驱动版本不匹配 | C 主责 | 固定版本；先 PIO 后 DMA，保留已知模式测试 |
| HDMI 带宽和 DDR3 不足 | A 主责 | 先 YUV/低分辨率/ROI，记录实际吞吐，不直接承诺四路 1080P |
| FPGA 前端资源或时序不足 | A 主责 | 先固定分辨率/ROI/规则流水线，记录资源和时序；将复杂分类和融合保留在 RK3568 |
| 三人集成阶段互相等待 | 全员 | M2 前冻结描述符，M3 前冻结决策消息，每个阶段都用模拟输入解耦 |
| 高阶四路拖垮基础演示 | C 负责决策 | M5 封版后再开 M6；高阶分支不得破坏单路稳定版本 |

## 7. 最终建议

三人组最稳妥的路线是：

```text
A 先打通 HDMI/DDR3
B 同时打通 RKNN/算法
C 同时打通 PCIe/协议
       -> M4 单路联调
       -> M5 基础封版
       -> M6 四路高阶扩展
```

不要把四路视频、复杂模型和 PCIe DMA 同时作为第一阶段目标。基础分拿到以后，再用独立分支做四路和高阶优化。

### S0：需求和评分拆解

C 建立一张需求矩阵，至少包含：

- 基础：图像采集显示、软硬协同通信、图像处理识别；
- 现场动作：红灯停车、绿灯通行、强制通行报警、虚线变道、实线直行、强制变道报警；
- 高阶：四路并行、复杂场景、AI 实时识别和辅助决策；
- 证据：功能测试记录、资源报告、时序报告、延迟数据、故障恢复记录。

A 负责把每个条目映射到 FPGA 模块，B 映射到算法/应用模块，C 映射到测试步骤和交付证据。

### S1：硬件可行性决策

这是整个项目最重要的决策门：

- 单路基础路线：一块 FMC HDMI 子卡即可；
- 四路高阶路线：需要四路 HDMI RX、视频聚合/解复用，或 HDMI + SFP/FMC 混合输入；
- 如果无法取得四路硬件，不得在报告中声称已完成“四路并行采集”，应把项目目标明确为基础任务和部分高阶任务。

C 负责向厂商索取资料，A 核对管脚和资源，B 根据实际输入路数决定模型调度方案。

### S2-S5：建立可用的软硬件底座

三人可以并行推进，但必须有明确的交接边界：

1. A 先完成单路 HDMI RX、DDR3 和直通；
2. C 同时完成 PCIe PIO 和 RK 设备树，不等真实视频；
3. B 同时在文件视频上完成 RKNN 和 OSD；
4. A/C 冻结帧描述符，C/B 冻结决策消息；
5. 只有已知模式 DMA 通过，才接真实 HDMI 帧。

### S6-S9：完成基础要求并封版

B 不应把所有识别都押在一个大模型上。建议首版采用“轻量检测 + 规则后处理”的组合：

- PP-YOLOE 或等效模型：行人、车辆、路障、交通灯候选；
- ROI 颜色/亮度规则：红、黄、绿灯分类；
- PP-LiteSeg 或传统图像算法：道路/车道/斑马线区域；
- OpenCV/规则：实线、虚线、箭头、报警 OSD。

C 将这些结果统一成决策状态机，A 保证输入帧号和输出结果不串帧。S9 必须打出一个不依赖四路输入的稳定版本，作为稳定保底版本。

### S10-S12：完成高阶要求

高阶扩展按以下顺序：

1. 先让四路输入各自能锁定、编号和单独显示；
2. 再做四路 DDR3 缓存和 PCIe DMA；
3. 再做四路 RKNN 调度和结果融合；
4. 最后做夜间、强光、遮挡和性能优化。

不要先做“一个模型同时处理四路”，再回头解决输入和 DMA；那会使问题无法定位。

### S13：系统验收

C 负责验收组织，A/B 提供测试结果：

- A：PDS 工程、约束、资源/时序、HDMI/DDR3/PCIe 运行结果；
- B：模型、推理结果、准确率/误报统计、NPU 延迟和内存占用；
